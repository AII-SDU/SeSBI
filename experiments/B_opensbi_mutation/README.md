# Legacy project-specific mutation experiments

This directory preserves the earlier OpenSBI target/control runs and the
RustSBI prototyper scope observation. It is superseded by the three-project
matched NAPOT experiment in `experiments/C_matched_napot_mutation/`, which
includes fresh raw logs and strict source/build evidence. In particular, the legacy RustSBI
`prototyper` row is now read as **NOT EXERCISED** by default `cargo test`, not as
an executed mutant that survived 209 tests.

The experiment tests whether native project test commands exercise and
distinguish selected boot-time mutation sites. It injects three variants based
on the SeSBI defect classes (NAPOT, pmpcfg, and mstatus) plus a positive control
into pristine upstream OpenSBI and runs **OpenSBI's own unit-test suite**.

## What was run

- Pristine upstream OpenSBI (base commit `2625712`), cloned fresh from GitHub.
- Its SBIUnit test suite enabled via `CONFIG_SBIUNIT=y` in
  `platform/generic/configs/defconfig`, built with `riscv64-linux-gnu-gcc`
  11.4.0, run under `qemu-system-riscv64` 6.2.0 (`make PLATFORM=generic run`).
- Baseline: all 41 unit tests across 8 suites pass.
- For each mutation: inject into the real code, rebuild, rerun the 41 tests,
  record whether any test flips to FAILED. Tree is `git checkout`-restored
  between mutations.

The maintained drivers locate their source trees relative to this repository.
`run_mutations_hardened.sh` accepts `QEMU_BIN`, `MAKE_BIN`, `TIMEOUT_BIN`,
`CROSS_COMPILE`, and `JOBS`; otherwise it uses conventional command names.
`run_mutations_rustsbi_hardened.sh` uses the repository's `rustsbi/` checkout
unless `RUSTSBI_DIR` is set. The legacy Linux-boot probe
`run_integration.sh` additionally requires `LINUX_IMAGE=/path/to/Image`; it no
longer assumes an image from the original author's machine.

## Result (`results.csv`)

| Mutation | Bug class | OpenSBI tests | Verdict |
|---|---|---|---|
| M1 | NAPOT addrmask off-by-one (`sbi_pmp.c`) | 41, 0 failed | **MISSED** |
| M2 | pmpcfg byte offset `n&7`→`n&3` (`sbi_hart_pmp.c`) | 41, 0 failed | **MISSED** |
| M3 | mstatus MPIE dropped in hart switch (`sbi_hart.c`) | 41, 0 failed | **MISSED** |
| M4 (control) | `log2roundup` off-by-one (`sbi_math.c`) | 41, 1 failed | **CAUGHT** |

## What it shows (and does not)

- **The three boot-critical bug classes (NAPOT, pmpcfg, mstatus) pass OpenSBI's
  own test suite unnoticed.** The reason is direct and checkable: OpenSBI's
  unit tests cover `math`, `string`, `atomic`, `locks`, `bitmap`, `bitops`,
  `console`, and `ecall`, but **no test exercises `pmp_set`/`sbi_pmp_encode`,
  the PMP config packing, or the hart-mode-switch `mstatus` update**. The code
  paths where our defects live are simply not unit-tested.
- **The control (M4) is caught.** `log2roundup` *is* unit-tested, and injecting
  an off-by-one there flips `log2roundup_test` to FAILED. This confirms the
  harness works and that "MISSED" for M1–M3 is a coverage gap, not a broken
  experiment.
- **Honest scope.** "Inadequate" here means specifically: OpenSBI's *unit
  tests* do not cover these boot-time encoding paths, so faults in them are not
  caught at that level. It does **not** mean OpenSBI ships these bugs (it does
  not; we injected them), nor that OpenSBI's *integration* testing (booting
  Linux under QEMU) could never surface them. It shows the class of low-level
  encoding logic that formal specification targets is outside the reach of the
  unit-test layer these projects rely on for fast, independent checking.

## Files

**Curated (combined) summary — reviewed by hand:**
- `results.csv` — the two-project table above (OpenSBI + RustSBI). Never written
  by any driver; it is the hand-curated combined view.
- `RESULTS.md` — full writeup with reading and honest scope.

**Raw machine-produced evidence (OpenSBI) — regenerated by re-running the driver:**
- `run_mutations_hardened.sh` — the hardened driver. Strict-fail: every
  substitution must hit its target an exact expected number of times
  (M1=1, M2=2, M3=1, M4=1) or the run aborts with no row; per-mutation source
  diff, original file, mutated object + firmware SHA-256, raw QEMU console, and
  filtered test summary are all saved. QEMU's expected post-test `timeout` kill
  (`qemu_exit=124`) is handled as completion, not failure; test counts are
  parsed from the console, not assumed.
- `results_raw.csv` — the driver's raw output (13-column schema with
  `injected`, `expected_hits`, `actual_hits`, `build_exit`, `qemu_exit`,
  `completed`, `obj_sha_changed`, `fw_sha_changed`). Written **only** by the
  driver; distinct from the curated `results.csv`.
- `logs_hardened/` — per-mutation `*.source.diff`, `*.<file>.orig`,
  `*.build.log`, `*.qemu.raw.console`, `*.test.summary`, `*.commands.txt`
  (exact commands + exit codes + SHAs), and `provenance.txt` (upstream commit
  `2625712`, local SBIUnit commit `98617cf`, GCC, QEMU, date).

**Raw machine-produced evidence (RustSBI) — regenerated by re-running the driver:**
- `run_mutations_rustsbi_hardened.sh` — the hardened RustSBI driver. Strict-fail
  like the OpenSBI one (RM1=1, RM2=1 exact hits or abort). It records, per
  mutation, the mutated package and whether that package is in the workspace
  `default-members` set that `cargo test` compiles (`cargo metadata`-derived),
  the source diff, the raw `cargo test` output, and test counts parsed from that
  output. RM1's legacy raw `MISSED` label is now interpreted as **NOT
  EXERCISED**, because `rustsbi-prototyper` is not in the `cargo test` compile
  set; RM2 (control) in the tested `sbi-spec` flips 2 tests to FAILED.
- `results_rustsbi_raw.csv` — the RustSBI driver's raw output (columns include
  `mutated_pkg`, `in_default_test_set`, `test_cmd`, `tests_total`,
  `tests_failed`, `completed`, `verdict`). Written **only** by that driver.
- `logs_rustsbi_hardened/` — per-mutation `*.source.diff`, `*.<file>.orig`,
  `*.cargo_test.out`, `*.commands.txt`, and `provenance.txt` (RustSBI commit
  `2ec490f`, rustc/cargo nightly, date).

**Superseded (kept for history):**
- `run_mutations.sh` — the earlier driver; its M1 substitution targeted the
  wrong file/variable after an upstream refactor and did not land, so its M1 row
  was an un-mutated baseline. Superseded by `run_mutations_hardened.sh`, which
  fails hard on exactly that condition.
- `logs/`, `logs/m1_napot.injection_proof.txt` — evidence from the earlier runs.
- `opensbi_upstream/` — the pristine clone (restored to baseline between runs).
